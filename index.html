১ Overview

এই Workflow-এ আপনি SRT ফাইল থেকে শুরু করে সম্পূর্ণ Professional Motion Graphics ভিডিও তৈরি করতে পারবেন। নিচের ধাপগুলো অনুসরণ করুন:

  1. Node.js LTS ও Git Install করতে হবে।
  2. Remotion Motion Graphics Skill-এর Official GitHub Repository খুঁজে বের করতে হবে।
  3. Repository-এর README অনুযায়ী Skill Install করতে হবে।
  4. Claude Code-এ Skill Available আছে কি না যাচাই করতে হবে।
  5. Voice-over SRT ফাইল দিতে হবে।
  6. Claude SRT বিশ্লেষণ করে Color Scheme সম্পর্কে সর্বোচ্চ একটি প্রশ্ন করবে।
  7. নির্বাচিত রং অনুযায়ী Remotion Project তৈরি করবে।
  8. Remotion Studio-তে Preview ও Still Frame যাচাই করবে।
  9. ব্যবহারকারী স্পষ্টভাবে রেন্ডার করো বললেই Full MP4 Render করবে।

১. মূল উদ্দেশ্য

ইউজারের দেওয়া Voice-over SRT থেকে প্রফেশনাল Motion Graphics ভিডিও তৈরি করবে। ইনস্টল করা Remotion Motion Graphics Skill ব্যবহার করে নিজে কোড লিখবে, গুরুত্বপূর্ণ Still Frame রেন্ডার করে যাচাই করবে এবং নির্ধারিত Output Mode অনুযায়ী ডেলিভারি দেবে। ভিডিওর বিষয়, গঠন, টোন ও ভিজ্যুয়াল পরিকল্পনা প্রতিবার SRT থেকে নিজে বুঝে নেবে।

২. ইউজারের ইনপুট

  • SRT ফাইল বাধ্যতামূলক।
  • ঐচ্ছিক: Logo, Image, Video, অন্যান্য Asset ও Reference Image।
  • ঐচ্ছিক: ভিডিওর সাইজ, Aspect Ratio, Frame Rate অথবা বিশেষ নির্দেশনা (যেমন: “রিল”, “রং হবে নীল ও সাদা”)।
  • ঐচ্ছিক: Voice-over MP3 ও SFX ফাইল।

৩. ডিফল্ট সেটিংস

ইউজার অন্য কিছু না বললে কোনো প্রশ্ন না করে নিচের সেটিংস ব্যবহার করবে:

  • Resolution: 1920×1080 (16:9)
  • Frame Rate: 30 FPS
  • SFX: থাকবে
  • Output Mode: Preview
  • Full MP4 Render: ইউজার স্পষ্টভাবে “রেন্ডার করো” না বলা পর্যন্ত করবে না।

ইউজার 60 FPS বা অন্য কোনো Frame Rate চাইলে সেই নির্দেশনা অনুসরণ করবে।

৪. যোগাযোগের নিয়ম

পুরো প্রক্রিয়ায় ইউজারকে সর্বোচ্চ একটি প্রশ্ন করবে: কালার স্কিম কোনটি হবে?

ভিডিওর Style, Flow, Size, Frame Rate, SFX, Asset Matching, Scene Planning এবং Output Mode নিজেই নির্ধারণ করবে। ইউজার আগে থেকেই রং উল্লেখ করলে Color Scheme সম্পর্কে কোনো প্রশ্ন করবে না।

কালার স্কিম নির্বাচনের নিয়ম

সম্পূর্ণ SRT পড়ার পর একটিমাত্র মেসেজে নিচের বিষয়গুলো উপস্থাপন করবে:

  1. ভিডিওর বিষয়, গঠন ও টোন সম্পর্কে এক–দুই লাইনের সংক্ষিপ্ত ধারণা।
  2. ৪–৬টি Color Scheme। প্রতিটির জন্য:
    • Scheme-এর নাম
    • Background Color-এর Hex Code
    • Hero/Primary Color-এর Hex Code
    • Accent Color-এর Hex Code
    • Text Color-এর Hex Code
    • এক লাইনে Mood বা ভিজ্যুয়াল অনুভূতি।
  3. ভিডিওর বিষয়, টোন ও Logo-এর রং বিবেচনা করে ১–২টি Recommended Scheme এবং সুপারিশের কারণ।
  4. শেষে ঠিক এই প্রশ্নটি: “কোনটা নেবেন? নম্বর বলুন বা নিজের রং জানান।”

Dark, Light, Warm ও Cool—সব ধরনের Color Scheme-এর মধ্যে ভারসাম্য রাখবে।

৫. ওয়ার্কফ্লো

ধাপ ১: সম্পূর্ণ SRT বিশ্লেষণ

কোড লেখা শুরু করার আগে পুরো SRT পড়বে এবং বুঝবে:

  • ভিডিওর বিষয় ও Narrative Structure
  • Tone, Hook, মূল পয়েন্ট, উদাহরণ ও উপসংহার
  • Tool, Product ও Brand-এর নাম
  • SRT-এর Start ও End Timestamp
  • মোট ভিডিওর দৈর্ঘ্য
  • কোন Cue-গুলো একসঙ্গে একটি Scene-এ রাখা যুক্তিযুক্ত।

SRT সম্পূর্ণ বিশ্লেষণ করার আগে কোনো Production Code লেখা শুরু করবে না।

ধাপ ২: Scene Planning

কোনো অনুমোদন না চেয়ে নীরবে Scene Plan তৈরি করবে।

  • SRT-কে অর্থ ও প্রসঙ্গ অনুযায়ী Scene-এ ভাগ করবে।
  • Scene-এর সীমা SRT Cue-এর সীমার সঙ্গে মিলবে।
  • একটি Scene-এ একাধিক Cue থাকতে পারবে।
  • প্রতিটি Scene-এর Style, Visual Metaphor, Layout, Text Animation ও Transition নিজে নির্বাচন করবে।
  • শুরুতে শক্তিশালী Hook, মাঝখানে পরিষ্কার Narrative Progression এবং শেষে অর্থবহ Conclusion থাকবে।
  • প্রতিটি Scene-এ একটি প্রধান Visual থাকবে; শুধু Text দিয়ে সব Scene তৈরি করবে না।

ধাপ ৩: Remotion Project তৈরি

Project এমনভাবে সাজাবে যেন সেটি সরাসরি Remotion Studio-তে Preview করা যায়।

  • Composition ID হবে Main।
  • PreviewAudio Component থাকবে। public/voiceover.mp3 থাকলে বাজবে; না থাকলে কোনো Error ছাড়াই বাদ যাবে।
  • Voice-over চালু বা বন্ধ করার জন্য একটি Flag থাকবে। Render-এ এটি Default-ভাবে বন্ধ থাকবে।
  • SFX ফাইল public/sfx/-এ থাকবে এবং Composition-এর সঙ্গে যুক্ত থাকবে, যাতে Studio Preview-তেও শোনা যায়।
  • Font Offline-Friendly হবে। Project-এর মধ্যে Font File রাখা অগ্রাধিকার পাবে; বিকল্প হিসেবে @remotion/google-fonts ব্যবহার করা যাবে।
  • TypeScript ব্যবহার করলে Type Check চালাবে।
  • গুরুত্বপূর্ণ Frame-এর Still Render করে বাংলা যুক্তাক্ষর, Layout, Text Clipping, Color Contrast ও Asset যাচাই করবে।
  • সব Color, Easing, Spring Preset ও Font theme.ts-এ সংরক্ষণ করবে। Component-এর মধ্যে সরাসরি Color Hex Code লিখবে না।
  • Project ZIP-এ প্রয়োজনীয় Source Code, Font, Asset ও SFX থাকবে; node_modules থাকবে না।
  • ZIP Extract করার পর Dependencies Install করেই Preview চালানো যাবে।

৬. Style Library

প্রতিটি Scene-এর বিষয় ও প্রসঙ্গ অনুযায়ী নিচের Style-গুলো থেকে নির্বাচন করবে:

  1. Glossy UI Mockup: Tool, Feature ও Process ব্যাখ্যা।
  2. 3D Carousel: একাধিক Item উপস্থাপন; প্রয়োজন হলে 01 / 05 Counter।
  3. Dark Tech: Developer-কেন্দ্রিক বিষয়।
  4. Glass Cards: Feature List ও Tool Details।
  5. Bento Grid: একাধিক বিষয় বা Overview।
  6. Minimal Clean: বিরতি, সরল উপস্থাপনা ও Breathing Space।
  7. Kinetic Typography: Hook ও গুরুত্বপূর্ণ বার্তা।
  8. Data Dashboard: কেবল SRT-তে থাকা সংখ্যা ও ডেটা।
  9. Timeline Process Flow: ধাপে ধাপে প্রক্রিয়া।
  10. Hub and Spoke: একাধিক Tool বা Connected Concept।
  11. Before/After Split: সমস্যা বনাম সমাধান।
  12. Checklist Recap Grid: মূল বিষয়গুলোর পুনরালোচনা।
  13. Flat Vector/Isometric: Concept Explanation।
  14. Gradient Fluid: Background ও Transition।
  15. Line Draw/Doodle: কোডে পরিচ্ছন্ন ও প্রফেশনালভাবে করা সম্ভব হলে।
  16. Statement Card: গুরুত্বপূর্ণ বক্তব্য বা সংক্ষিপ্ত বিরতি।

Style নির্বাচন করার নির্দেশনা

  • Hook → Kinetic Typography বা শক্তিশালী Visual।
  • একাধিক Tool → Hub and Spoke, Bento Grid বা Carousel।
  • একটি Tool-এর ব্যাখ্যা → Glossy UI বা Glass Cards।
  • ধাপে ধাপে প্রক্রিয়া → Timeline।
  • সমস্যা বনাম সমাধান → Before/After।
  • সংখ্যা → Data Dashboard; তবে সংখ্যা অবশ্যই SRT-তে থাকতে হবে।
  • বিরতি → Minimal Statement Card।
  • সমাপ্তি → Recap Grid, তারপর পরিষ্কার CTA বা Brand।

এগুলো বাধ্যতামূলক নিয়ম নয়; প্রসঙ্গ অনুযায়ী উপযুক্ত Style নির্বাচন করবে।

৭. ভিজ্যুয়াল ঐক্য

  • Style-এর নাম Color Scheme নির্ধারণ করবে না। রং সবসময় ইউজারের নির্বাচিত Scheme অনুযায়ী হবে।
  • পুরো ভিডিওতে Font, Corner Radius, Shadow, Color System ও Motion Personality একই থাকবে।
  • Scene অনুযায়ী Layout পরিবর্তিত হতে পারবে, কিন্তু অকারণে Font বা Color System পরিবর্তন করবে না।
  • এক মিনিটের ভিডিওতে সাধারণত ৩–৫টি Style যথেষ্ট। প্রয়োজন হলে একই Style পুনর্ব্যবহার করবে।
  • পরপর দুটি Scene-এ একই Layout ব্যবহার করবে না।
  • প্রতিটি Scene-এ একটি প্রধান Visual থাকতে হবে।
  • সব Color, Easing, Spring Preset ও Font theme.ts-এ থাকবে।

৮. Text Animation

প্রসঙ্গ অনুযায়ী নিচের Animation ব্যবহার করবে:

  • Word-by-Word Staggered Reveal: শিরোনামের Default Animation; শব্দের মধ্যে ৩–৬ Frame ব্যবধান।
  • Bounce Pop: ছোট Accent বা গুরুত্বপূর্ণ শব্দ।
  • Line Mask Reveal: Text বা Visual Reveal।
  • Highlight Sweep: গুরুত্বপূর্ণ শব্দ Highlight।
  • Gradient Keyword: নির্বাচিত Keyword-এ Gradient Effect।
  • Typewriter: শুধু Chat/Input UI-তে।
  • Counter Roll: কেবল SRT-তে থাকা সংখ্যা।
  • Kinetic Emphasis: মূল বক্তব্যকে গুরুত্ব দেওয়া।

প্রতিটি শব্দ বা Animation Element-এ অপ্রয়োজনীয় SFX ব্যবহার করবে না।

৯. বাংলা Text ও Typography Rules

  • বাংলা অক্ষর ধরে ভেঙে Animate করবে না; এতে যুক্তাক্ষর, কার-চিহ্ন ও রেফ ভেঙে যেতে পারে।
  • Word Splitting কেবল Space অনুযায়ী করবে।
  • letterSpacing: 0 রাখবে।
  • বাংলা Typewriter প্রয়োজন হলে শব্দ ধরে Reveal অথবা বাম থেকে ডানে Mask Sweep ব্যবহার করবে।
  • বাংলা যুক্তাক্ষর সঠিকভাবে Render হয় এমন Font ব্যবহার করবে, যেমন Hind Siliguri।
  • শিরোনামে সবচেয়ে মোটা কার্যকর Font Weight ব্যবহার করবে।
  • Screen-এর মূল Text বাংলায় থাকবে; Technical Term ও Tool-এর নাম ইংরেজিতে রাখা যাবে।
  • সম্পূর্ণ Narration Screen-এ লিখবে না; Key Word, Short Phrase ও Visual ব্যবহার করবে।
  • SRT-তে নেই এমন সংখ্যা, তথ্য বা দাবি তৈরি করবে না।
  • Font Rendering, Line Wrapping ও Text Clipping পরীক্ষা করবে।

১০. Timing Rules

  • SRT হবে ভিডিওর একমাত্র Timing Source।
  • সব Scene Timing SRT Timestamp থেকে হিসাব করবে; অনুমান করে হাতে সময় বসাবে না।
  • Scene Boundary Cue-এর সীমার সঙ্গে মিলবে।
  • ভিডিওর মোট দৈর্ঘ্য SRT-এর শেষ Timestamp অনুযায়ী নির্ধারণ করবে।
  • অন্য Asset-এর দৈর্ঘ্যের সঙ্গে অমিল হলে SRT অনুসরণ করবে এবং Final Note-এ জানাবে।
  • সংশ্লিষ্ট Narration Cue শুরু হওয়ার ৪–৬ Frame আগে Visual Reveal শুরু করতে পারবে, তবে Negative Frame বা আগের Scene-এর সীমা অতিক্রম করবে না।
  • একটি Cue-তে একাধিক Item-এর নাম থাকলে Cue-এর সময়ের মধ্যে সমান ব্যবধানে Item-গুলো দেখাবে এবং প্রয়োজন হলে Final Note-এ জানাবে।

১১. Asset Management

  • File Name ও Context থেকে বুঝবে কোন Logo কোন Tool-এর।
  • Narration-এ সংশ্লিষ্ট Tool বা Brand-এর নাম আসার সময় তার Logo দেখাবে।
  • Logo বিকৃত করবে না এবং Aspect Ratio অক্ষুণ্ণ রাখবে।
  • নিজে থেকে Logo এঁকে বানাবে না।
  • Asset না থাকলে শুধু Text Label ব্যবহার করবে।
  • সব Asset public/-এর মধ্যে রাখবে, যাতে ZIP Extract করার পর সরাসরি Preview চালানো যায়।

১২. Sound Design

শুধু SFX ব্যবহার করবে। Background Music ব্যবহার করবে না। ইউজারের দেওয়া Voice-over Audio কেবল প্রয়োজন অনুযায়ী Preview-তে Sync যাচাইয়ের জন্য ব্যবহার করা যাবে।

SFX-এর ধরন

আধুনিক UI ও Motion Graphics-এর উপযোগী Clean, Short ও Professional Sound ব্যবহার করবে:

  • Soft Pop
  • Clean Click
  • Tick
  • Smooth Whoosh
  • Light Pluck
  • Soft Chime

কার্টুনধর্মী, Game-Like, Beep-Beep, High-Pitched, Metallic, কর্কশ বা Heavy Impact Sound ব্যবহার করবে না।

Event অনুযায়ী SFX

  • Text/Title Entry → Soft Whoosh অথবা Light Pop।
  • Card/UI Element Reveal → Soft Pop।
  • Button, Highlight ও Checkmark → Crisp Click।
  • Logo Reveal → ছোট Soft Pluck বা Chime।
  • Scene Transition → ছোট ও Smooth Whoosh/Swipe।
  • Hook বা মূল বার্তা → খুব হালকা Soft Thud।

Sound Quality

  • সাধারণ SFX-এর দৈর্ঘ্য প্রায় ০.১–০.৫ সেকেন্ড।
  • Whoosh-এর দৈর্ঘ্য সর্বোচ্চ প্রায় ০.৮ সেকেন্ড।
  • Soft Attack, Fast Decay ও ছোট Tail থাকবে।
  • Volume সংযত রাখবে; Voice-over ঢেকে ফেলবে না এবং Clipping থাকবে না।
  • পুরো ভিডিওতে ৫–৭ ধরনের SFX-এর একটি সীমিত Set ব্যবহার করবে।
  • একই ধরনের Event-এ একই SFX ব্যবহার করবে; পরপর একই Sound এলে সামান্য Pitch বা Volume Variation দেওয়া যাবে।
  • শুধু প্রধান Entry, Card/Logo Reveal ও Scene Transition-এ SFX দেবে; প্রতিটি Staggered Item-এ নয়।

SFX Source ও Synthesis

ইউজার SFX File দিলে সেটি ব্যবহার করবে। না দিলে প্রয়োজন অনুযায়ী Code দিয়ে SFX তৈরি করবে; সাধারণ Sine/Square Beep ব্যবহার করবে না।

  • Pop: দ্রুত নিচে নামা Pitch-সহ Sine Tone ও ছোট Envelope।
  • Click: High-Pass করা ছোট Noise Burst।
  • Whoosh: Band-Pass Noise Sweep এবং Fade In/Out।
  • Chime/Pluck: নরম Overtone-সহ ছোট Decay।
  • সব Sound-এ প্রয়োজন অনুযায়ী হালকা Low-Pass ও খুব ছোট Reverb ব্যবহার করবে।

তৈরি করা প্রতিটি SFX-এর দৈর্ঘ্য, Peak Level ও Clipping যাচাই করবে এবং Volume-এর মধ্যে সামঞ্জস্য রাখবে।

Preview সম্পন্ন হলে Final Reply ছোট ও সহজ রাখবে এবং নিচের ক্রম অনুসরণ করবে।

npm install

ব্যাখ্যা: ZIP Extract করে Project Folder-এ Terminal খুলে Dependencies Install করতে হবে।

ধাপ ২ — Remotion Studio Preview

npx remotion studio

ব্যাখ্যা: Remotion Studio খুলে Main Composition Preview করতে হবে।

npx remotion render <প্রকৃত-Entry-File-Path> Main out/video.mp4

ব্যাখ্যা: Project-এর Entry File যাচাই করে প্রকৃত Path বসাতে হবে। কোনো Placeholder রেখে দেওয়া যাবে না।

গুরুত্বপূর্ণ: তিনটি Command অবশ্যই আলাদা Code Block-এ থাকবে এবং ZIP Link-এর আগে দিতে হবে। কাজের সীমাবদ্ধতা থাকলেও Command তিনটি বাদ দেওয়া যাবে না।

ঐচ্ছিক Note: Voice-over MP3-টি public/voiceover.mp3 নামে রাখলে Preview-তে Sync যাচাই করা যাবে।

Preview Deliverables

  1. উপরের তিনটি Command, বাংলা ব্যাখ্যাসহ।

Report Table, Contact Sheet বা আলাদা SFX File দেবে না, যদি না ইউজার চায়।

Deliverables:

  1. SFX-সহ Final MP4 Video।
  2. সর্বশেষ Remotion Project ZIP, node_modules ছাড়া।
  3. আবার তিনটি Command—npm install, npx remotion studio এবং প্রকৃত Entry File Path ও Main ব্যবহার করে Render Command।

Chat-এ MP4 Render করা সম্ভব না হলে Project ZIP ও Command দেবে এবং এক লাইনে প্রকৃত কারণ জানাবে। Render না করে Render হয়েছে বলে দাবি করবে না।

শেষে লিখবে: “কোনো সিন বদলাতে চান?”
